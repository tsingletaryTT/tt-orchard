# Open issue triage, 2026-10-30

Prompt (operator): take a break from bringing up models; analyse the open issues, rank them, and label them. This document and the GitHub labels are the only outputs. No code changed, no issue was closed or edited, no comment was posted, and no hardware was used.

## How this was made

All 78 open issues were read in full (body and every comment). Each was checked against the merged pull requests (160 listed by `gh pr list --state merged`), the dated log in `docs/project-log.md`, `docs/run-logs/`, and the code on `main` at commit b2e80f0 (for example the hostile-input registry in `tests/hostile_inputs.py`, `orchard/hwtool.py` and `tests/test_audio_stage0_coder.py`). Where an issue's last comment is older than a merged PR that touches it, the status below follows the PR. Open pull request 296 (chunked prefill, trace-safe) is the only open PR; statuses that depend on it say so.

Limits. Nothing was run. A status that says done comes from reading the PRs, the log and the code. It was not re-tested. The closure candidates need the operator's eyes before any issue is closed.

## E. Themes and risks

* **Chip wedges keep recurring.** Issues 26 (fabric timeouts), 276 (a cached-tensor load that never returns), 290 (a trace-on timing run) and 25 (a board off the bus) each describe a run that left a chip or board unusable, and each has a different trigger. Only 290 has a watchdog harness (PR 291). A shared rule is missing: every hardware run writes a line before each iteration and uses a timeout shorter than gozer's reap window. 32 of the 78 issues need hardware, so wedges and queueing set the pace of everything else.
* **The readers backlog is nearly done.** The hostile-input registry has no known defects left for issues 136 to 139 (PR 148, 249, 283). The remaining risk is the unregistered modules: 55 modules that parse JSON are still on the backlog list in `tests/hostile_inputs.py`, and each new module that parses JSON (PR 291 added `prefill_bench.py`) has to be added by hand. Issue 287 is the only open defect of this kind: a refused file can read as no decision.
* **Review findings filed after merge.** Issues 218, 219, 220, 225, 227, 258, 259, 288, 293 and 297 are Copilot findings left open at merge time. Four are already fixed (219, 258, 259, 293 once PR 296 lands) and stay open only for want of a close. Filing the Mediums is useful and the closing step is missing; a sweep after each merge would keep the list accurate. Ten of the 78 open issues are in this group.
* **Cards, listening and licences.** Nobody has listened to the Stable Audio 3 or ACE-Step clips (160, 270, 271). Issue 270 shows two copies of ACE-Step model code that give a waveform correlation of 0.65 and nobody knows which is intended. MiniCPM3's card quotes a weights-licence statement whose link was unreachable (PR 260). Issue 21 needs credentials the harness does not hold, and every Hub upload needs the operator's go-ahead (271). Decisions on these are cheap for the operator and block packages.
* **Serving correctness at concurrency and sampling.** Issues 83, 107 and 182 point at the same gap: published packages serve a configuration (host sampling, drafter off, or greedy-only drafter) that was measured at one request at a time and at one sampling setting. The tool-call damage at 4 concurrent requests is the only wrong-result finding in the list that a published package depends on.
* **Tracking issues drift.** 28, 59, 89, 160 and 254 are summaries that went out of date within days of being written. The next-round plan (PR 257) said the hazard scan was not wired the day before PR 292 wired it. Treat tracker text as a pointer and trust the linked issues.
* **New-code models are still hand-driven.** The text route and the audio path run models whose code a person wrote first (MiniCPM3, Stable Audio 3, ACE-Step, Granite). No issue yet covers the harness writing a port. 90 and 94 are that work, and 94 (the write boundary) has to precede it.
* **Kernel work has moved to the chip.** Simulator passes did not predict chip compiles (205). With the verified pair (PR 223, 228, 240) the next kernel measurement should be done on the pair. 96, 175 and 176 overlap and should be read as one thread.
* **Non-language models have no owner.** 28 of 50 catalog packages are perception, image, speech or other kinds, and no open issue plans for them.
