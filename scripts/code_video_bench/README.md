# code-video benchmark harness

Runs the public `code-video` skill of SenseNova-6.8-Code2Video under Qwen Code, against any OpenAI-compatible endpoint, inside a locked-down container, and measures what happened. The first runs and their results are in `docs/run-logs/2026-11-03-sensenova-code-video-qwen-code.md`.

| File | What it does |
|---|---|
| `Dockerfile` | The sandbox image: Node 24, Python with numpy, scipy, soundfile and librosa, ffmpeg, Playwright with Chromium, `@napi-rs/canvas`, Qwen Code 0.26.0. No `edge-tts` (it sends text to an outside service) and no `faster-whisper` (it downloads models), so films are silent. It has no Pillow; add it if a brief needs it (one pilot tool error came from that). |
| `run_bench.sh` | One run: task directory, skill installed unchanged (source path and file hashes recorded in `logs/`, outside the container), Qwen Code settings, metric sampling, the container. Every host python call uses `python3 -I -S` after the script has unset every `PYTHON*` variable, and the exit trap removes the container it created through a bounded `docker rm` (`CVBENCH_CLEANUP_TIMEOUT_S`, default 60; a failure is written to `logs/cleanup.log` with the id). Needs `WORK_ROOT` (made absolute; no colon or line break) and `SKILL_SRC`. The run name uses letters, digits, `.`, `_` and `-`. The run directory is reserved with one atomic `mkdir` before anything slow starts, so a second invocation with the same name is refused and touches nothing of the first; a start that fails before it writes anything gives the name back. The container is named `cvbench-RUN_NAME-HASH`, where the hash comes from the reserved directory's path. Every python call runs as `python3 -I`. Cleanup removes only the container this run created, by the id docker wrote to `logs/container.id`; the deadline is `timeout -k 60`, so a workload that ignores SIGTERM still ends. |
| `collect.sh` | The way to start `collect.py`: `collect.sh RUN_DIR WIDTH HEIGHT FPS MIN_DUR MAX_DUR [IMAGE]`. It makes `RUN_DIR` absolute, unsets every `PYTHON*` variable, changes to `/` and runs `python3 -I -S collect.py` (`CVBENCH_PYTHON` names another interpreter). |
| `poll_metrics.py` | Samples the server's `/metrics` (running and waiting requests, token counters) so a run can say whether anyone else used the endpoint. Series that differ only in the engine or model labels are added together. |
| `collect.py` | Summarizes a finished run: stream statistics, server load, and ffprobe, the skill's own `check_video.sh` and per-frame hashes of `out/final.mp4`, all checked in a read-only container with no network. The checker runs from a trusted read-only copy of the skill (`SKILL_SRC`, or the path the run recorded), never from the task directory the model could edit: its working directory is that copy, it gets the video by absolute path, and its Python runs with `PYTHONSAFEPATH`, `PYTHONNOUSERSITE` and an empty `PYTHONPATH`, so a `json.py` the model left in the task cannot be imported in its place. Start the collector with `collect.sh`, which unsets every `PYTHON*` variable, leaves the caller's working directory and runs `python3 -I -S`; `collect.py` refuses to run without `-I` (startup code python ran before the script's first line cannot be undone from inside it). Every other container call runs from an empty read-only scratch directory. Every read of the task directory goes through one anchored reader that opens each directory with `O_NOFOLLOW` from a descriptor and takes only regular files: a link anywhere on a path, a FIFO, a device or a dangling link is refused and listed in `refused_paths`, never followed and never reported by its target's size. The agent's stream and the metric samples are read line by line to a byte cap (`CVBENCH_STREAM_CAP_BYTES`, default 512 MiB; a line over `CVBENCH_LINE_CAP_BYTES`, 4 MiB, is skipped and counted), and a container call is read while it runs and stopped at its output cap (`CVBENCH_OUTPUT_CAP_BYTES`, default 64 MiB on stdout, at most 1 MiB on stderr) as well as at its deadline. The summary lists skill files the run changed. A measurement that could not be taken (a container that timed out or that docker refused, ffmpeg that failed or wrote anything but framemd5 records, a hash count that disagrees with ffprobe's frame count) is `null` with the reason in an `error` field, and `measurement_failures` lists and counts them; a missing measurement is never zero, and gauge counts say how many samples carried each gauge. Each container is bounded by `CVBENCH_DOCKER_TIMEOUT_S` (default 900) and removed by its id on a timeout or an output over its cap; a removal that fails or times out (`CVBENCH_CLEANUP_TIMEOUT_S`, default 60) is listed in `cleanup_failures` with the container id and the reason, and collection goes on. |
| `tests/test_code_video_bench.py` | Runs the three scripts through their command lines with stand-ins for docker, curl, systemd-run, ffprobe and ffmpeg: no container or server is started. |
| `briefs/` | The dense production prompts used (written by Claude following the upstream `prompts/enhance_prompt.md`; the model under test did not write them). |

The container gets only the task directory, no credentials, no capabilities, a read-only root file system and memory and process limits. It shares the host network namespace because the endpoint listens on loopback. Start runs as detached units (`systemd-run --user --unit=...`) so closing the terminal does not stop them. Keep the endpoint to yourself during a run, or the timing numbers include the other client; `poll_metrics.py` records when that happened.
